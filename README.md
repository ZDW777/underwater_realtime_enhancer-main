# 水下图像 / 视频实时增强工作台

## 项目简介

这是一个基于 PySide6、PyTorch 和 TensorRT 的水下图像与视频增强桌面程序。程序可以加载图像、视频或摄像头画面，在统一界面中选择增强模型、推理后端和处理分辨率，并实时对比 Original 与 Enhanced 结果。

当前项目以 Python 3.12、PyTorch 2.8.0、CUDA 12.8 为目标环境，主要面向 NVIDIA GPU 推理。TensorRT engine 需要根据模型和输入尺寸提前生成，界面程序负责模型发现、权重匹配、推理、预览和结果保存。

## 项目功能

- 自动扫描 `models/`，按“文件名与主网络类名相同”的约定识别模型。
- 支持通过可选的 `model_registrations.toml` 集中指定网络类和构造参数。
- 输出范围按配置固定，默认使用 `0_1`；支持全局默认值和单个模型覆盖，不再逐帧猜测范围。
- 支持 PyTorch、TensorRT FP16、TensorRT INT8。
- 支持 3840×2160、2560×1440、1920×1080、1280×720 和自定义分辨率。
- 支持图像、视频文件、图像/视频混合文件夹和摄像头 0。
- 底部“设置”窗口可保存默认模型、推理模式、分辨率与自定义宽高，下次启动自动恢复。
- PyTorch 支持“自动匹配”，逐个文件保持原始尺寸，奇数宽高也能增强与保存。
- Windows 摄像头首次完整检测，后续快速复用成功配置；异常时重新协商，并显示真实采集尺寸和实采帧率。
- Original 与 Enhanced 双窗口同步预览。
- 视频开始播放前预缓存 30 帧，降低短时推理波动带来的卡顿。
- 视频文件在推理较快时按源 FPS 播放，较慢时自动按实际处理能力显示。
- 摄像头独立采集最新原始帧，增强预览按合并的新帧通知显示，避免历史画面和通知积压。
- 预览使用与界面窗口匹配的缩略图，保存仍使用完整分辨率结果。
- 显示 GPU 推理耗时、GPU 推理 FPS 和实际显示 FPS。
- 支持开始、暂停/继续和结束；结束后两个预览窗口恢复为等待界面。
- 增强图像保留原文件名及格式，增强视频保存为 MP4。

## 启动设置与文件夹输入

### 启动默认选项

点击左下方“结束”右侧的“设置”，在居中小窗口中选择启动后的默认选项。窗口使用与主界面一致的深海蓝配色。点击“保存”同时应用到当前空闲界面并保存为下次启动值；点击“取消”不改变已保存的偏好。运行期间设置按钮不可用，防止改动当前任务参数。

| 设置 | 行为 |
| --- | --- |
| 默认增强模型 | 使用当前成功识别的模型名；该模型以后被删除时提示并回退到现有模型 |
| 默认推理模式 | PyTorch、TensorRT FP16、TensorRT INT8 |
| 默认处理分辨率 | 预设、自定义或自动匹配；自动匹配仅在PyTorch下可选 |
| 自定义宽高 | 随自定义选项一同保存；从设置窗口保存后视为已确认 |
| 存放位置 | QSettings用户级INI，通常为 `%APPDATA%/UnderwaterVision/RealtimeEnhancer.ini`；不写入源码或模型注册文件 |
| 保存时机 | 只有设置窗口点击保存才持久化；主界面临时切换选项不会覆盖启动默认值 |

### 选择文件夹与批处理

主界面使用同一个“选择图像 / 视频 / 文件夹”按钮。进入选择窗口后，可以直接打开单个媒体文件，也可以进入目标目录再点击“选择当前文件夹”。

| 项目 | 规则 |
| --- | --- |
| 内容 | 全部图像、全部视频或混合内容都可处理；子目录和非媒体文件忽略 |
| 顺序 | 开始时固定当前目录清单，按文件名排序，不递归子目录 |
| 进度 | 输入源栏显示当前序号、总数、媒体类别与文件名，悬停查看完整路径 |
| 后端复用 | 一批文件复用一次加载的模型/engine，文件间重置性能样本和播放状态 |
| 视频 | 每段单独保留源FPS与原有30帧预缓冲，前一段消费完成后再开始下一项 |
| 图像 | 每项快速预览，主线程复制后再允许下一项，避免大图信号积压 |
| 坏文件 | 无法读取/解码的媒体记录原因并跳过；模型、显存或写盘错误中止并明确报错 |
| 暂停/结束 | 控制整个文件夹任务；结束后不再启动后续文件 |
| 保存 | 需勾选“保存增强结果”；图像保留原文件名及扩展名，视频保留原主文件名并继续输出MP4，不追加额外后缀 |

## PyTorch原尺寸自动匹配

在“处理分辨率”的“其他 / 自定义”下方选择“自动匹配”，也可将它保存为启动默认值。每张图像和每段视频按真实解码帧尺寸处理，文件夹中不同尺寸分别匹配；底部摘要显示当前实际输出尺寸。这个模式不创建`0x0`权重目录，所有尺寸仍共用同一个PyTorch checkpoint。

| 情况 | 处理方式 |
| --- | --- |
| 图像640×377 | 不拉伸输入；默认只在右侧/底部复制边缘补到8的倍数，推理后裁回640×377 |
| 不同尺寸的图像/视频混合 | 复用模型，逐个文件确定尺寸；视频以第一张真实帧为准 |
| 特殊网络的尺寸约束 | 单模型集中配置`input_multiple` > 模型模块`INPUT_MULTIPLE` > 默认8；无倍数约束可配置1 |
| 输出约束 | 网络应保持补边后输入的空间尺寸；若输出不符明确报错，不偷偷resize增强结果 |
| TensorRT或摄像头 | 仍使用明确固定尺寸；切换到这类输入/后端时自动匹配选项不可用 |
| 奇数尺寸视频保存 | 使用已有imageio-ffmpeg所带FFmpeg，以H.264 4:4:4写入MP4，保留奇数宽高；部分播放器可能不支持4:4:4 |
| 偶数尺寸或固定模式保存 | 保留原OpenCV mp4v编码路径 |

`input_multiple`仅影响PyTorch自动匹配补边，不改变网络结构或固定尺寸推理。例如虚构模型要求16的倍数：

```toml
[models.ExampleAlignedNet]
input_multiple = 16
```

原尺寸需要模型支持可变输入；固定位置编码、多输入、非等尺寸输出等网络仍需专用适配。补边避免几何拉伸，但边缘特征可能与直接按原尺寸推理不同。视频中途变化尺寸会明确报错，请先拆分该视频。保存仍不包含音轨，也不会改变原有按源FPS写入文件头的规则。

## 摄像头自动适配

点击“开始增强”后，相机按当前处理尺寸（所选权重的输入尺寸）选择采集模式。采用“首次完整检测、后续快速复用、异常时重新协商”的策略。运行中切换尺寸需要先结束，再选择新尺寸并重新开始。

### 检测与缓存复用

| 场景 | 程序行为 |
| --- | --- |
| 首次使用某个原生采集模式 | 查询驱动能力，分别短测可用后端，记录成功配置 |
| 同一设备、同一模式再次开始 | 直接打开成功后端，验证真实帧、尺寸、格式和回报FPS，不重复比选测速 |
| 更换模型但原生采集模式相同 | 共享成功配置；例如4K与2K模型都采用原生4K采集时可以复用 |
| 选择尚未测试过的原生模式 | 复用能力清单，对这个新模式完整比选后端 |
| 设备列表或设备身份发生变化 | 清除旧缓存，重新查询能力和检测 |
| 缓存后端无法确认、打开/读帧失败或生效参数不符 | 释放失败设备，清除对应配置，自动重新查询能力并完整协商 |
| 运行中发生采集故障或超过5秒没有新帧 | 报错并清除缓存，下次点击开始时完整检测；不反复自动重连 |
| 正常暂停、结束 | 保留成功参数；结束仍释放相机，不把设备句柄留在缓存中 |
| 关闭并重新启动程序 | 进程内缓存消失，重新完整检测，不创建缓存配置文件 |

缓存按设备唯一路径与原生采集尺寸、格式、帧率建立，不按模型名建立，也不保存旧设备序号。每次仍查询一次当前设备列表，并重新匹配后端身份；因此快速复用不会盲信上次的摄像头编号。缺少唯一路径或能力枚举失败时不缓存兼容协商结果。

完整比选顺序为DirectShow、MSMF，两个后端不会同时占用同一相机。速率相差不超过5%时优先MSMF；若最后测试的后端胜出，直接保留已打开的采集器。若必须重新打开之前的优胜者，只验证帧与生效参数，不重复完整测速。每轮完整测速排除两次启动读取，至少观察约0.6秒；快速复用后的实采FPS在运行中持续统计。

只对尚未满足的宽度、高度和FPS设置属性，减少驱动重复重建采集链路；仍以真实帧验证结果为准。相机打开、首次出帧和必要的参数设置仍需要时间，快速复用不等于瞬间启动。悬停详情中的协商耗时不包含模型/engine加载。

### 模式选择与校验

| 项目 | 规则 |
| --- | --- |
| 驱动能力查询 | 使用 `imageio-ffmpeg` 自带FFmpeg读取DirectShow公布的尺寸、格式、帧率组合 |
| 跨后端设备匹配 | Windows API枚举MSMF，优先匹配设备路径，名称只在两边均唯一时使用；无法确认则仅使用DirectShow |
| 原生尺寸匹配 | 同尺寸优先，选择该尺寸最高标称FPS，相同FPS优先MJPEG |
| 无对应原生尺寸 | 优先相近宽高比、无需放大、像素量较接近的模式；1440p可用4K采集后缩小，1920×1072可由1080p适配 |
| 参数生效验证 | 检查实际uint8三通道BGR帧、实际尺寸与回报FPS，不以 `set()` 成功作为生效依据 |
| 格式设置与解释 | 尺寸/FPS处理后再请求FOURCC；DirectShow校验传输格式，MSMF的22等值按输出格式解释，不当成MJPEG四字符码 |
| 防止低速静默回退 | 同尺寸存在更快模式时，跳过低于最高标称FPS一半的模式；仍失败则尝试其他尺寸，并在详情中说明 |
| 依赖/能力查询失败 | 明确提示，回退到目标尺寸、MJPEG/默认格式、30 FPS兼容请求；不声称已经选到硬件最高帧率 |
| 输入缩放 | 采集与模型同尺寸时跳过输入resize；不同时保留一次缩放，不影响完整尺寸输出与保存 |

安装依赖：`python -m pip install -r requirements.txt`。Windows设备枚举使用标准库和系统API，不需额外COM包。驱动未公布的原生尺寸、60/120 FPS不能靠软件凭空增加；“800万像素”也不等于高帧率。

正常运行时保留中文字段，显示如下：


| 显示位置 | 内容 |
| --- | --- |
| 输入源主框 | 设备、后端、采集尺寸、模型尺寸、实采FPS；已选低帧率模式时保留简短警告 |
| 实采尚未形成样本 | 显示“实采-测量中”，不使用标称值或启动采样冒充实采速度 |
| 悬停详情 | 完整设备名、格式（包括BGR输出/格式值22）、标称FPS、比选采样、实采FPS、启动方式、协商耗时、缩放与回退原因 |
| 协商过程中 | 显示完整检测、快速复用或缓存校验失败后的重新协商进度 |

### 运行、停止与保存

| 项目 | 行为与边界 |
| --- | --- |
| 原始采集 | 独立线程读取，应用层最多缓存1帧；推理只取新序号的最新帧，慢时允许跳过中间原始帧 |
| 增强预览 | 最多缓存1帧，合并新帧通知；不使用视频的30帧预缓冲、显示定时轮询或低水位0.97降速 |
| 暂停/恢复 | 暂停推理和预览，采集继续刷新；清除过期预览并丢弃暂停前尚未完成的旧结果，暂停时间不计入显示FPS |
| 正常结束 | 唤醒消费者，由采集线程退出并自行释放设备，后续可复用参数重新打开 |
| 驱动永久阻塞 | 不跨线程强行释放正在读取的设备；等待释放超过4秒显示提示，退出窗口也等待安全释放，需检查USB或驱动 |
| 保存 | 完整模型输出按相机标称FPS写MP4文件头；实际帧数由处理速度决定，开启保存增加编码/写盘成本，需单独测速 |
| 性能限制 | 曝光、USB带宽、解码、GPU调频和完整链路仍会影响速度；驱动内部缓存不同于应用层单帧缓存 |

自动适配不修改曝光、增益、白平衡或GPU电源策略，不默认增加平滑缓冲、锁频、CUDA Graph或特定OpenCV线程数。上述相机策略不影响视频文件原有的播放逻辑。

## 添加模型

程序同时支持同名自动识别和集中注册，两种方式可以混合使用。普通模型无需填写注册信息，特殊模型只需修改根目录中的 `model_registrations.toml`，不用改动模型源码。下文的 `ExampleNet`、`AlternativeExample` 等均为虚构示例名。

### 方式一：同名识别、默认构造

把模型文件放入 `models/`，让文件名（去掉 `.py`）与主网络类名完全一致，区分大小写。例如：

```text
models/ExampleNet.py  →  class ExampleNet(nn.Module)
```

最小示例：

```python
from torch import nn


class ExampleNet(nn.Module):
    def __init__(self) -> None:
        super().__init__()
        # 填写与训练权重一致的网络结构

    def forward(self, x):
        return x
```

程序选择 `ExampleNet`，在开始 PyTorch 推理时调用 `ExampleNet()`。文件中可以存在其他辅助网络类，不会被当作主网络。不需要在模型源码中额外添加注册信息。

自动识别要求主网络在当前文件中定义，继承 `torch.nn.Module`，并且能够使用默认参数构造。若构造函数含必填参数，或默认参数与训练配置不同，请使用方式二。

### 方式二：单独文件集中注册

编辑根目录下的 `model_registrations.toml`。该文件默认包含 `[defaults]` 的 `output_range = "0_1"`、注释示例和空的 `[models]` 表，不会给项目添加虚构模型；删除该文件也不会影响同名自动识别，此时使用内置默认范围 `0_1`。

例如，`models/LegacyExample.py` 中定义了 `AlternativeExample(channels, num_blocks=4)`，可以只在配置文件中添加：

```toml
[models.ExampleNet]
file = "LegacyExample.py"
class_name = "AlternativeExample"
init_kwargs = { channels = 64, num_blocks = 4 }
requires_weights = true
output_range = "0_1"
```

程序会在界面中显示 `ExampleNet`，并调用 `AlternativeExample(channels=64, num_blocks=4)`。权重也按注册名 `ExampleNet` 查找，例如 `weights/pth/ExampleNet.pth`。

| 字段 | 含义与默认值 |
| --- | --- |
| `[models.注册名]` | 注册名同时用作界面模型名和权重文件的模型名前缀；不同注册项必须使用不同名称 |
| `file` | `models/` 下的单个 `.py` 文件名；省略时使用 `注册名.py`，不支持子目录或绝对路径 |
| `class_name` | 显式选择当前文件中定义的主网络类；省略时使用文件同名类 |
| `init_kwargs` | 传给主网络类的关键字参数；省略时为 `{}`，即默认构造；参数必须与训练配置一致 |
| `requires_weights` | 是否加载 PyTorch 权重；省略时沿用模型的 `REQUIRE_WEIGHTS`，模型未声明时为 `true`；TensorRT 仍需要 engine |
| `output_range` | 固定输出范围；省略时沿用模型的 `OUTPUT_RANGE`，模型未声明时使用 `[defaults].output_range`，内置默认值为 `"0_1"` |
| `input_multiple` | PyTorch自动匹配的补边倍数，1至1024的整数；省略时沿用模块`INPUT_MULTIPLE`，模型未声明时为8；固定尺寸不受影响 |

显式注册的文件不再额外生成自动识别条目，其他文件继续自动识别。同一文件也可通过不同注册名创建多个参数配置，但每个配置应使用对应的权重。

修改配置或添加、删除模型代码后，在界面点击“刷新”。刷新阶段导入模型并校验入口与构造参数，不会实例化网络或执行推理。模型文件顶层应避免直接启动训练、测速或分配 GPU 显存；这些代码应放在 `if __name__ == "__main__":` 中。

### 输入输出约定与异常提示

模型输入约定仍为 RGB、NCHW、范围 `[0, 1]`。输出范围按以下优先级解析：

```text
单个模型的集中配置 output_range
              ↓ 未设置
模型已有的 OUTPUT_RANGE
              ↓ 未设置
[defaults].output_range
              ↓ 未设置
内置默认值 0_1
```

输出转换规则固定如下，最终统一得到 `uint8` BGR 图像：

| 配置 | 转换规则 |
| --- | --- |
| `0_1` | 裁剪到 `[0,1]`，乘以 255 |
| `minus1_1` | 按 `(x+1)/2` 转换，裁剪到 `[0,1]`，乘以 255 |
| `0_255` | 裁剪到 `[0,255]` |

例如，可在集中配置文件中设置全局默认值，并只为特殊模型覆盖。以下模型名均为虚构示例，使用时应填写实际模型名：

```toml
[defaults]
output_range = "0_1"

# 输出采用 [-1,1] 的虚构模型
[models.ExampleSignedNet]
output_range = "minus1_1"

# 输出采用 [0,255] 的虚构模型
[models.ExampleByteNet]
output_range = "0_255"
```

普通同名模型不必逐个填写，`[defaults]` 也不会将模型加入注册列表。该表只支持 `output_range`；省略该表或该字段时使用内置默认值 `0_1`。

使用集中配置的 `output_range` 时，不需要在模型源码中再添加 `OUTPUT_RANGE`。这只是对模型真实输出约定的声明，不会改变网络结构、训练权重或输入预处理。应与训练目标及导出过程保持一致。

范围在刷新模型时解析，并直接保存在不可变的 `ModelSpec.output_range` 中。PyTorch 和 TensorRT 后端读取同一个已确定值，推理期间不会根据某一帧的最小值、最大值或负数比例改变转换方式。少量负值和超过上限的值只按既定范围裁剪。

旧的 `auto` 值保留作为迁移标记，含义改为“固定使用全局默认范围”，不再自动猜测；即使模型自身声明了其他范围，集中配置显式写 `auto` 时仍使用全局默认值。`[defaults].output_range` 自身写为 `auto` 时使用内置默认值 `0_1`。同一来源在相同默认值下，每次程序运行只在运行终端提示一次 `UserWarning`，不会逐帧重复提示，也不会将模型判为识别失败。

预览和保存共用后端生成的增强帧，执行完全相同的范围转换；预览只额外缩小画面，保存仍使用完整处理尺寸。NaN 在最终数值转换前置零，正、负无穷分别裁剪到对应显示上限和零。

文件不存在、同名主网络缺失、类不是 `nn.Module` 子类、构造参数缺失、注册字段错误、依赖导入失败或模型名重复，都会通过现有窗口底部状态栏明确报告，其他有效模型仍可识别。构造函数实际执行失败或构造结果异常时，会在开始处理后通过现有错误弹窗报告。

能够定位到文件的注册项出错时，该文件不会静默回退到自动识别，以免使用错误的网络或参数。整个 TOML 文件语法错误时，会报告配置文件错误，并继续尝试同名自动识别；请先修正配置再运行需要特殊参数的模型。

全局默认项类型、字段或范围值错误时，会单独报告 `[defaults]` 错误，并使用内置默认值 `0_1` 继续识别；单个模型仍可通过有效的配置或 `OUTPUT_RANGE` 声明覆盖。

如果模型使用特殊归一化、多输入、多输出或其他颜色空间，需要在 `core/backends.py` 中增加专用适配。

## 权重路径与命名

### PyTorch

PyTorch checkpoint 不区分输入分辨率，直接放在：

```text
weights/pth/模型名.pth
```

例如：

```text
weights/pth/ExampleNet.pth
```

程序支持普通 `state_dict`、常见 checkpoint 字典、直接保存的 `nn.Module`，并会自动移除 DataParallel 的 `module.` 前缀。

### TensorRT

TensorRT engine 通常绑定固定输入尺寸，需要按后端和分辨率分类：

```text
weights/trt16/宽x高/模型名_宽x高_trt16.engine
weights/trt8/宽x高/模型名_宽x高_trt8.engine
```

虚构模型 `ExampleNet` 的 FP16 路径示例：

```text
weights/trt16/3840x2160/ExampleNet_3840x2160_trt16.engine
weights/trt16/2560x1440/ExampleNet_2560x1440_trt16.engine
weights/trt16/1920x1072/ExampleNet_1920x1072_trt16.engine
weights/trt16/1280x720/ExampleNet_1280x720_trt16.engine
```

文件名统一使用具体的 `宽x高`，不要使用 `4k`、`2k`、`1k` 或 `720p` 等简称。模型名称和大小写必须与界面识别到的模型名一致：同名自动识别时使用文件名，集中注册时使用注册名。

TensorRT engine 应满足：

- 一个图像输入和一个图像输出；
- batch 为 1；
- 输入形状为 `[1, 3, H, W]`；
- 输入输出格式为 TensorRT `LINEAR`；
- 固定输入尺寸与界面选择完全一致；
- 推荐使用浮点输入输出，在 engine 内部完成 FP16 或 INT8 计算。

## 使用说明

1. 点击“选择图像 / 视频 / 文件夹”，打开媒体文件或在选择窗口中点击“选择当前文件夹”；也可以选择“使用摄像头 0”。
2. 选择增强模型和推理模式。
3. 选择处理分辨率。
4. 检查权重提示是否显示“已找到”。
5. 如需保存结果，勾选“保存增强结果”并选择目录。
6. 点击“开始增强”。
7. 运行中可以暂停、继续或结束。

### 使用 1920×1072 engine

1920×1072 不在标准分辨率列表中，需要选择：

```text
处理分辨率：其他 / 自定义
宽度：1920
高度：1072
```

程序会查找：

```text
weights/trt16/1920x1072/ExampleNet_1920x1072_trt16.engine
```

源视频分辨率不必与 engine 相同。例如 2K 或 4K 视频也可以使用 1920×1072 engine，程序会在推理前将源帧缩放到 1920×1072。engine 尺寸必须匹配界面选择的处理分辨率，而不是源视频分辨率。

## 预缓冲与显示策略

| 输入 | 启动与缓冲 | 显示节奏 |
| --- | --- | --- |
| 普通视频文件 | 先缓存30帧，显示“正在预缓冲 n/30” | 足够快时跟随源FPS，较慢时按处理能力降低速度 |
| 少于30帧的短视频 | 读取完成后播放已有缓存 | 沿用视频文件播放规则 |
| 摄像头 | 首次检测/缓存复用后开始，原始和增强缓冲各最多1帧 | 按合并新帧通知显示，来不及时丢弃旧帧以减少延迟 |

视频预缓冲只能平滑短时波动，不能提高模型的长期推理速度。

### 预览和保存

Original 与 Enhanced 预览会缩小到接近界面控件尺寸，并使用 `QImage.Format_BGR888` 直接显示BGR图像。保存路径仍接收完整分辨率结果，因此缩略预览不会降低输出质量。

## 性能指标

| 指标 | 含义 |
| --- | --- |
| GPU 推理耗时 | CUDA Event 测得的模型或engine执行时间 |
| GPU 推理FPS | `1000 / 平均GPU推理耗时(ms)` |
| 实际显示FPS | Enhanced新帧真正进入Qt绘制事件的帧率 |

| 统计项 | 规则 |
| --- | --- |
| TensorRT预热 | 视频/相机前20帧不进入GPU与处理耗时样本，仍正常显示和保存；显示FPS始终按真实新帧绘制计算 |
| 统计窗口 | 最近60帧滑动平均 |
| 界面指标更新 | 每200 ms更新，显示一位小数 |
| 相机实采更新 | 输入源摘要/详情每秒最多更新一次，独立于GPU与绘制统计 |
| 单张图像 | 不具连续播放意义，显示FPS可保持为 `--` |

GPU推理FPS通常高于实际显示FPS。视频解码、resize、数据传输、输出转换、视频写入和Qt绘制都会影响最终显示速度。

相机另外在输入源栏报告实采FPS。内部处理耗时包含等待最新原始帧、推理、后处理、可选保存和预览生成；它与GPU执行耗时分开统计。模型足够快时，实际显示通常跟随实采速度，例如30 FPS相机不会因为GPU推理超过100 FPS就产生100张新的相机画面。GPU调频和其他负载仍会影响推理读数，不能据此承诺瞬时FPS不变。

## 结果保存

| 项目 | 行为 |
| --- | --- |
| 图像 | 保留原文件名及扩展名，按原格式编码；单图和文件夹图像规则一致 |
| 视频/摄像头 | 保存为MP4，采用完整模型输出尺寸 |
| 文件命名 | 图像、视频均不附加enhanced、时间戳或其他后缀；摄像头无原文件名，继续使用时间戳和纳秒后缀 |
| 视频扩展名 | 原视频为MP4时完整保留名称及扩展名；其他格式仍转换为MP4，如`clip.avi → clip.mp4` |
| 同名结果 | 重复保存到同一目录会更新同名结果；输出与原图/原视频为同一文件时明确报错，请另选输出目录 |
| 批内重名 | 若同一文件夹的不同来源转为MP4后同名（如`clip.avi`与`clip.mp4`），开始处理前报错；请分开处理或调整源文件名 |
| 点击结束 | 完成已打开的视频文件并提示保存路径；停止恰好打断等待相机新帧时也会提示 |

```text
2_img_.png
cv_1062.mp4
```

输出使用模型完整分辨率。例如选择 3840×2160 engine 时，界面虽然显示缩略图，保存结果仍为 3840×2160。

当前视频使用 OpenCV `VideoWriter` 和 `mp4v` 编码，只保存画面，不保留原视频音轨。

## 注意事项

1. TensorRT engine 通常与 TensorRT、CUDA、操作系统和GPU架构相关，修改文件名不能解决兼容性问题。
2. 固定尺寸必须精确匹配，例如 1920×1072 和 1920×1080 不能互换。
3. 4K推理仍需要较高显存；缩略预览只降低显示开销，不降低模型推理显存。
4. 开启视频保存会增加编码和写盘负载，实际显示FPS可能下降。
5. 当前TensorRT通用后端只支持单输入、单输出和线性NCHW图像。
6. 当前摄像头编号固定为0，输出视频不包含声音。
7. 替换模型或engine前应先结束当前任务。

## 常见问题

### 模型没有出现在下拉框

确认模型文件位于 `models/`，自动识别的文件没有以下划线开头，并且存在文件同名的 `nn.Module` 主网络类。同名类必须在当前文件中定义，且默认构造不缺少必填参数。

若使用集中注册，检查 `model_registrations.toml` 的文件名、`class_name` 和 `init_kwargs`，再点击“刷新”。模型依赖缺失、配置错误或导入失败等原因会显示在窗口底部状态栏。辅助模块可以以下划线开头，避免被当作独立模型扫描。

### 找不到权重

按照界面显示的相对路径检查文件。重点确认模型名大小写、具体宽高、目录层级和 `_trt16/_trt8` 后缀。

### TensorRT engine 无法加载

通常是 TensorRT版本、CUDA、GPU架构、操作系统或插件环境不兼容。建议在目标电脑的当前环境中重新构建 engine。

### Enhanced黑屏、偏色或出现规则纹理

检查以下内容：

- engine 导出前是否加载正确训练权重；
- 训练、ONNX、TensorRT和界面是否统一使用 RGB、NCHW、`[0, 1]`；
- 集中配置的 `output_range`、模型的 `OUTPUT_RANGE` 或全局默认范围是否与模型真实输出一致；
- ONNX和TensorRT输出是否与PyTorch结果接近；
- engine 输入输出是否为 `LINEAR`。

少量负值本身不代表模型采用 `[-1,1]`。对于按 `[0,1]` 训练的模型，应使用 `0_1` 并裁剪越界值；将整帧错误地按 `minus1_1` 转换会抬亮暗部，使画面发白。当前程序已取消逐帧范围猜测，避免由范围切换造成明暗跳变。

### 点击开始后暂时没有画面

视频正在填充30帧缓存。4K或较慢模型需要更长等待时间；摄像头和单张图像不会执行30帧视频预缓冲。

相机首次使用某个采集模式还需查询能力和比较后端，之后直接验证并复用成功配置；缓存校验失败时自动完整重协商。设备打开和必要的模式设置仍需时间，详情中的协商耗时不包含模型加载。输入源栏显示进度，悬停可查看回退原因及启动方式；重启程序会清空缓存。

### GPU FPS很高但画面仍然较慢

GPU FPS只统计模型执行时间。查看“实际显示FPS”，并考虑视频解码、前后处理、保存和Qt绘制开销。可以尝试降低处理分辨率、关闭结果保存或使用TensorRT FP16。

### CUDA显存不足

降低处理分辨率，关闭其他GPU程序，并避免同时启动多个界面实例。部分4K模型可能需要进一步实现分块推理。

---

项目将模型、权重解析、推理后端、媒体工作线程和Qt界面分开组织。新增符合通用输入输出约定的同名模型时，只需放入网络代码和对应权重；特殊入口或构造参数可以通过可选的集中注册文件指定。
